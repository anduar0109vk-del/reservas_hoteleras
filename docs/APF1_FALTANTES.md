# APF1: elementos que faltan en el documento de trabajo

Este inventario compara `trabajo.docx` con la consigna de APF1 y el sílabo de
Herramientas de Desarrollo. Incluye únicamente los elementos que deben
incorporarse al documento, no capítulos que ya están desarrollados.

## Evidencias que faltan

1. **Organigrama de Casa Andina como imagen o diagrama**  
   El documento contiene la descripción de áreas, pero el espacio destinado a
   la estructura organizacional está vacío. Usar
   `diagrams/organigrama-casa-andina.mmd`.
2. **Lean Canvas completo como imagen**  
   El documento solo presenta el título y una introducción. Usar
   `diagrams/lean-canvas-casa-andina.mmd`.
3. **Mockups de las tres alternativas**  
   Se describen las pantallas, pero no se adjuntan las evidencias visuales de
   las tres alternativas. La consigna exige al menos cinco pantallas por
   alternativa. Incorporar cinco capturas por alternativa y rotularlas como
   Figura 1 a Figura 15.
4. **Diagrama de casos de uso del sistema**  
   Es necesario para completar el análisis SRS exigido por la rúbrica. Usar
   `diagrams/casos-uso-reservas.mmd`.
5. **Diagrama de proceso**  
   Falta una representación visual del flujo reserva-confirmación-check-in-
   check-out. Usar `diagrams/proceso-reserva.mmd`.
6. **Diagrama entidad-relación y diagrama de clases legibles**  
   El documento de trabajo no contiene estos diagramas. Usar
   `diagrams/entidad-relacion-reservas.mmd` y
   `diagrams/diagrama-clases-reservas.mmd`.
7. **WBS y Gantt actualizados al periodo real**  
   El Project Charter usa fechas 10/09/2026–10/12/2026. Debe reemplazarse por
   11/08/2026–12/12/2026. Usar `APF1_PLAN_2026.md` como fuente para construir
   las imágenes.
8. **Evidencias de trabajo en la empresa**  
   Adjuntar fotografías, acta, entrevista o validación de requerimientos. No
   inventar evidencias: si no se dispone de ellas, solicitar la validación al
   docente o al representante de Casa Andina.

## Elementos del sílabo que deben evidenciarse en el informe

- Repositorio GitHub, ramas, commits y Pull Requests.
- Flujo de integración continua y resultado de la compilación.
- Gestión de incidencias o tareas mediante Issues/Projects.
- Para las siguientes entregas: entrega continua, contenedores y despliegue.
